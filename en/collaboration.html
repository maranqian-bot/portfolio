Collaboration

How I Work with a Team

These are the collaboration standards I followed with the team while delivering projects. Spec-driven development; based on them, I aligned branch strategy, commit conventions, Issue management, and PR and code-review procedures with the team and operated them consistently.

Workflow

Rather than implementing a feature immediately, I first confirm requirements and specs, agree on the scope, and then begin implementation.

1

Confirm Issue · Requirements

I first organize features, bugs, and improvements as Issues.

2

Review · Write Spec Documentation

I review the relevant spec; when none exists, I write it in the order spec · plan · tasks.

3

Agree on Implementation Scope

I start only after aligning the implementation plan and scope with the team.

4

Create a Branch

from the latest develop to create a feature branch.

5

Implement and Validate

I follow the existing code style and structure, then validate the implementation with tests.

6

Create a Pull Request

I open a PR focused on one purpose and explain the intent of the change.

7

Merge after Review

I apply review comments, resolve the threads, and then merge.

Branch Strategy

I always branch developfrom the latest branch, name it to reflect the work, and keep one purpose per branch.

Branch Naming

feature/{work-name}
fix/{work-name}
refactor/{work-name}
docs/{work-name}
chore/{work-name}

Rules I Follow

  • I never create a new branch on top of work already in progress.
  • If a branch is created incorrectly, I preserve the changes and recreate it from develop as the base.
  • For sequentially dependent features, I state the merge order and dependent branch in the PR body.

Commit Convention

I follow {type}({branch-name}) : {summary} format so the change intent is clear from the commit message alone, and split commits into reviewable units.

TypeMeaning
featAdd a feature
fixFix a bug
refactorRefactor
styleChange code format or style
designChange UI/UX
choreOther configuration or documentation
renameRename a file or name
removeRemove
buildChange build configuration
# Example
feat(feature/user-login-api) : add member login API
fix(fix/payment-status-validation) : fix payment-status validation error

Issue Management

I split features, bugs, and improvements into Issues, record progress and completion criteria, and make the workflow visible to the team.

How I Split Issues

I separate features, bugs, and improvements into individual Issues to make each unit of work clear.

Records I Keep

I record progress and completion criteria in the Issue so the completed work and scope are clear.

Pull Request

I always open PRs against developand use the team template to record related Issues, work modules, changes, verification results, and reviewer notes. Before opening a PR, I check the following items.

✓Whether the work branch was created from develop(with merge order and dependent branch stated for sequential dependencies)
✓Whether the PR scope focuses on one purpose
✓Whether unrelated file changes are excluded
✓Whether it conflicts with the Spec or Convention
✓Whether required tests or build checks were completed
✓Whether reviewer notes are included in the PR body

Code Review

I record review comments and changes alongside the implementation result, preserving how the team improved it together.

Review Handling Principles

  • I clearly mark every comment as addressed, deferred, or rejected.
  • When I do not apply a suggestion, I leave the reason in the comment.
  • I add the fix commit to the existing PR branch and mark the thread resolved.

AI · Automated Review

  • I also apply valid findings from automated reviews such as CodeRabbit.
  • I clean up simple style warnings when they do not conflict with team rules.
  • For findings that do not match the current code, I leave the evidence and skip them.

Testing & Validation

I run the following commands for each stack and record the results in the PR. For documentation-only changes, I also explain why validation was skipped.

# Backend
cd backend && ./gradlew test

# Frontend
cd frontend && npm run build

# FastAPI
cd fastapi && python -m pytest
